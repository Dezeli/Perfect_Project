# 완벽그자체 프로젝트

박재형을 위한 서버 없는 안드로이드 성장 기록 앱. React Native + Expo + TypeScript.

## 현재 단계: 프로필·퀘스트 + 손글씨 사진 초안 + 스토리 제작

- 짙은 녹색과 금색의 RPG 테마, 코드로 그린 픽셀 캐릭터
- 첫 실행 이름 입력, 이후 저장된 프로필로 자동 시작, 설정에서 이름 변경
- 빈 퀘스트 목록으로 시작하며 예시 기록을 실제 데이터로 생성하지 않음
- 직접 퀘스트 등록·수정·삭제, 날짜와 성장 영역 및 경험치 선택
- 완료·미달성 처리와 취소, 완료 기록에서 누적 경험치 및 레벨 계산
- 날짜별 퀘스트 조회, 과거 기록 수정, 미래 날짜의 퀘스트 예약 (미래 완료는 차단)
- SQLite 로컬 저장: 앱 재실행 후 이름과 퀘스트 유지
- 캐릭터와 시작 장비 표시는 시각적 초안. 장비 조작 화면은 후속 단계에서 구현
- 날짜별 노트 사진 여러 장 등록: 카메라/갤러리 → 종이 영역 자르기 → 기기 내 저장
- 사진별 OCR 원문과 AI 테스트용 입력 텍스트를 별도 보관
- 사진 선택·삭제, 앱 재실행 후 사진과 텍스트 유지
- 퀘스트 설정에서 손글씨 사진을 선택하면 한국어 OCR → 기기 내 Gemini Nano 해석 → 입력칸 초안 채우기
- 인식 전으로 되돌리면 직전 입력칸과 사진 기록을 복구. 저장하기 전에는 퀘스트와 XP에 반영하지 않음
- 퀘스트 탭의 `스토리 만들기`에서 실천 사진·영상 최대 3개 선택. 한 항목당 별도 9:16 MP4 스토리 한 편 생성
- 저장된 손글씨 계획 사진을 기본으로 사용하거나 다른 사진으로 변경·제외 가능. 퀘스트, 날짜, XP, 이름·레벨·픽셀 캐릭터를 영상에 표시
- 영상은 앞부분 최대 20초를 사용해 약 5초로 배속하고, 사진은 5초 영상으로 변환. 초안에서는 원본 오디오를 제거
- 제작 결과를 앱에서 미리 보고 각각 갤러리에 저장하거나 공유 가능. 내보낸 파일은 앱 캐시에 있으므로 보관하려면 갤러리에 저장해야 함
- OCR·AI·스토리 제작의 실제 기기 실행은 아직 미검증. 파일 백업·복원은 아직 연결하지 않음

## 실행

```powershell
npm.cmd install
npm.cmd start
```

PC와 휴대폰을 같은 Wi-Fi에 연결하고 SDK 57에 맞는 Expo Go에서 QR 코드를 스캔합니다.
연결이 안 되면 `npm.cmd start -- --tunnel`을 사용합니다.
이전 개발 서버가 실행 중이라면 Ctrl+C로 종료하고 `npm.cmd start -- --clear`로 다시 시작합니다.
Expo Go에서는 사진 등록·조회·삭제와 텍스트 직접 입력/저장이 가능합니다. 자동 OCR과 기기 AI는 사용할 수 없습니다.
개발 서버 연결 및 의존성 설치에는 네트워크가 필요합니다. 최종 오프라인 앱은 별도로 빌드합니다.

## 자동 OCR·기기 AI·스토리 제작용 안드로이드 개발 APK

OCR 모듈은 `modules/perfect-ocr/`의 Kotlin 코드로 구현했습니다.
`com.google.mlkit:text-recognition-korean:16.0.1`을 앱에 포함하므로 실행 시 모델 다운로드를 하지 않습니다.
AI 해석은 ML Kit Prompt API의 Gemini Nano를 사용합니다. 지원 기기에서 모델이 준비돼 있으면 오프라인으로 실행되며, 준비되지 않았다면 첫 실행에 모델 다운로드가 필요할 수 있습니다.
Expo Go에는 이 모듈이 없어 개발 APK를 설치해야 합니다.
스토리 제작도 `modules/perfect-story/`의 Android Media3 Transformer 네이티브 모듈을 사용하므로 Expo Go에서는 버튼을 눌러도 영상을 만들 수 없습니다.

EAS 클라우드 빌드 (Expo 계정 로그인 및 최초 프로젝트 설정 필요):

```powershell
npx.cmd eas-cli@latest login
npx.cmd eas-cli@latest build --platform android --profile development
```

생성된 APK를 휴대폰에 설치한 다음 아래 명령을 실행하고, Expo Go 대신 설치한 개발 앱으로 연결합니다.

```powershell
npm.cmd run start:dev -- --clear
```

클라우드 빌드에는 소스가 빌드 서비스로 전송됩니다. 빌드 후 OCR 실행은 기기에서만 이루어집니다.
클라우드 빌드를 실제로 요청하지는 않았습니다. 이 환경에는 JDK/Android SDK가 없어 APK 컴파일은 아직 확인하지 못했습니다.
로컬 빌드는 Android Studio/JDK/SDK를 설정한 뒤 `npm.cmd run android -- --device`로 진행할 수 있습니다.
루트 `android/`는 자동 생성된 폴더이므로 직접 수정하지 않고 `app.json`과 `modules/perfect-ocr/`를 수정합니다.

공식 안내: [Expo 개발 빌드](https://docs.expo.dev/develop/development-builds/introduction/), [한국어 ML Kit OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android), [기기 내 Prompt API](https://developers.google.com/ml-kit/genai/prompt/android/get-started).

## 검증

```powershell
npm.cmd run typecheck
npx.cmd expo export --platform android
npm.cmd run lint
npm.cmd test
npx.cmd expo-doctor
```

테스트는 TypeScript를 직접 읽는 Node.js 24 환경에서 확인했습니다.
타입 검사, 린트, 경험치·날짜·여러 노트·AI 응답 파싱 테스트를 실행합니다.
실제 기기에서의 화면·저장 동작은 사용자의 확인이 필요합니다. JS 번들 생성은 APK 빌드가 아닙니다.

## 휴대폰에서 확인할 항목

1. 처음 실행 시 이름 입력 후 모험 화면으로 이동하는지
2. 퀘스트를 등록하고 완료·미달성·취소할 때 경험치가 일치하는지
3. 이전/다음 날로 이동해서 날짜별 퀘스트를 조회할 수 있는지
4. 설정에서 이름을 바꾸면 모험 화면에도 반영되는지
5. 앱을 완전히 종료했다가 다시 열어도 이름과 퀘스트가 남는지
6. 모험 → 손글씨 노트에서 같은 날의 사진을 여러 장 추가·선택·삭제할 수 있는지
7. 사진별 테스트 텍스트를 저장하고 앱을 다시 열어도 유지되는지
8. 개발 APK에서 자동 인식을 실행하고 사진별 OCR 원문이 보관되는지
9. 퀘스트 설정에서 사진 인식 초안이 뜨고, 되돌리기가 입력값과 사진 기록을 복구하는지
10. 개발 APK에서 사진·영상을 2~3개 선택했을 때 스토리가 각각 한 편씩 만들어지는지
11. 손글씨 사진·퀘스트·캐릭터가 미리보기에 표시되고 각 스토리의 갤러리 저장·공유가 되는지

현재 노트는 날짜별 최대 30장, 인식/입력 텍스트는 사진별 12,000자까지 보관합니다.
사진은 선택·자르기 이후 긴 변 최대 2048px JPEG로 저장합니다. 카메라/갤러리 원본은 수정하지 않습니다.
OCR 결과에 규칙 기반 오타 교정은 적용하지 않습니다. AI 초안은 저장하기를 누를 때만 퀘스트와 경험치에 반영합니다.
재인식 시 저장된 테스트 입력을 유지하며, 사진별 원문과 별도로 확인할 수 있습니다.

Expo Go 삭제, 앱 데이터 초기화, 최종 앱 삭제 시 로컬 기록은 사라집니다.
현재 Expo Go의 기록을 향후 독립 APK로 자동 이전하지 않습니다. 그 단계 전에 백업·복원을 구현합니다.

## 화면 구성과 장비 초안 (2026-10-14)
- 홈 / 목표 / 통계 세 탭. 설정 아이콘은 홈에 두고, 무기·방어구 아이콘을 누르면 소유 장비 선택 창이 열립니다.
- 메인 문구: 완벽그자체 {이름} 프로젝트. OFFLINE 배지는 제거했습니다.
- 무기와 방어구 두 슬롯, 시작 장비 각 1개. 장비 8종은 임시 이름과 효과입니다.
- 고정 XP / 영역별 XP / 퍼센트 XP / 하루 첫 달성 / 올클리어 효과.
- 완료 보상을 저장하고 장비 변경과 완료 취소 후 재달성에도 같은 보상을 사용합니다.
- 올클리어 보상은 해당 날짜의 첫 올클리어 당시 고정하며 목표 추가·완료 취소로 모두 달성 조건이 깨지면 회수합니다.
- 100 XP마다 레벨업. 처음 도달한 레벨마다 뽑기권 1장. 같은 레벨의 보상은 반복 지급하지 않습니다.
- 초안 확률: 일반 60%, 희귀 30%, 영웅 10%. 중복 장비는 보유 목록에 추가하지 않으며 중복 보상은 아직 없습니다.
- 이전 저장 기록과 XP는 유지하고 장신구 슬롯은 제거합니다. 이전에 도달한 레벨의 뽑기권은 소급 지급하지 않습니다.
- 캐릭터는 임시 표시입니다. 실제 무기·방어구 에셋의 외형 적용, 공유 이미지 생성, 백업·복원은 후속 작업입니다.
- 검증: 타입 검사 / 린트 / 테스트 19개. 실제 Android 화면은 기기에서 확인이 필요합니다.

## 글꼴과 화면 정리
- 글꼴은 `assets/fonts/`에 보관하고 앱 시작 시 번들에서 불러옵니다.
- 제목·레벨은 Mulmaru, 짧은 라벨은 Neo둥근모, 본문·입력은 Pretendard를 씁니다.
- 글꼴 라이선스와 출처는 `assets/fonts/licenses/` 및 `assets/fonts/README.md`에 있습니다.
- 홈은 프로젝트 시그니처, 캐릭터·레벨·장비 중심으로 구성하고, 퀘스트와 기록은 별도 탭에 둡니다.
- 화면의 영문 장식 라벨, 중복 설명, 길게 표시하던 온보딩 문구를 정리했습니다.
